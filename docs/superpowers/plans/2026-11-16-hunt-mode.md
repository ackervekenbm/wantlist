# Hunt Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every idea a second mode, Hunt, that finds the cheapest real offer for an exact product, ranked by delivered price, with purchases, a Pantry and Running low.

**Architecture:** Hunt is a mode of the existing idea (`ideas.mode`, `ideas.target`). A hunt run goes through the same worker and `PipelineEngine`, which dispatches to a new `research/hunt.ts`; its offers are stored as `picks` rows with `kind = 'offer'` and an `offer` JSON column, ranked in code by `research/rank.ts`. A new `purchases` table holds what was paid. The client shows a `HuntView` instead of the pick deck when the idea is in Hunt.

**Tech Stack:** TypeScript, Express 5, better-sqlite3, React 19, Vite, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-16-hunt-mode-design.md` (read it with this plan; mockups `docs/design/quote-slip/shots/09`, `11`, `14`, `16`).

**Issue:** #53, branch `feat/hunt-mode`, one PR with `Fixes #53`.

## Global Constraints

- Verification for every task: `npm run build && npm test` (build = typecheck, lint, vite build, server tsc).
- Tests sit next to the code (`foo.ts` → `foo.test.ts`); shared helpers only in `src/server/test/helpers.ts` and `src/client/test/fakeApi.ts`. Tests never touch the network.
- Migrations are append-only (migration 7) and must tolerate databases from before versioning (`addColumn` is idempotent). Picks are never deleted by a run.
- A hunt run makes at most 3 model calls (plan, select offers, verify offers), at most 4 Serper queries, reads at most 10 offer pages (`PageCache`, 6 in flight).
- `SHOP_RULES` applies to every hunt model step unchanged; queries Dutch, Serper `gl=be`, `hl=nl`.
- Delivery is never guessed: only what a page states; otherwise `unknown`, shown as "delivery not shown".
- UI: Quote Slip tokens only (`--*` in `styles.css`, light and dark), brass marks Hunt, targets ≥ 44 px, `prefers-reduced-motion`, works at 390 px and two panes from 900 px.
- Copy: English UI; eyebrow "HUNT · REFILL" / "HUNT · ONE-OFF" (just "HUNT" while `refill` is null); "Best real offer"; "✓ checked <time>"; "Bought here"; "Open shop"; "Will you buy this again?"; "Yes, it's a refill" / "No, one-off"; "Covered"; "Running low"; "You paid"; "Hunt this one"; "delivery not shown".
- Never name other repos in files, commits or the PR.

## Review Focus

1. **Free over a threshold, item below it, cost not stated** → delivered price is unknown, not free. Pinned in Task 2.
2. **Every exact offer behind a bot wall (unchecked price)** → no best offer; the run fails `no-results` with the hunt message instead of crowning a search price. Pinned in Task 4.
3. **A database from before Hunt** → every idea reads as `mode: 'explore'`, every pick as `kind: 'pick'`, `purchases: []`. Pinned in Task 1.
4. **Running low on an idea that is not covered, or twice in a row** → 409, nothing queued twice. Pinned in Task 5.
5. **Undo of a purchase that is not the newest** → only that row goes; the list stays as it is. Pinned in Task 1.
